# 桌面端打包指南

> 适用：`desktop_client`（Electron 33 + Vue 3 + Vite + better-sqlite3）
> 产物：Windows NSIS / macOS DMG / Linux AppImage·deb·rpm，输出到 `release/` 目录

---

## 1. 前置条件

| 项 | 要求 | 说明 |
|---|---|---|
| Node.js | 已装（当前 v24） | `node -v` 确认 |
| 依赖 | 已安装 | 未装先执行 `npm install` |
| better-sqlite3 | 已针对 Electron ABI 编译 | `npm install` 的 postinstall 会自动处理；失败时执行 `npm run rebuild` |
| VS Build Tools | 兜底需要 | 预编译二进制命中时不需要；编译失败时装「使用 C++ 的桌面开发」负载 |
| 打包图标 | `build/icon.ico` | 已就位（256x256，蓝色渐变聊天气泡 W 图标），源图 `build/icon.png` |

---

## 2. 打包命令

### 正式打包（生成安装包）

```powershell
cd e:\vibe-coding\new_im\desktop_client
npm run build        # 默认打当前平台的安装包（本机即 Windows NSIS）
```

等价于 `vite build && electron-builder`：先构建前端到 `dist/`，再打安装包。

产物位置：`release/`，Windows 形如 `检车家IM Setup 1.9.0.exe`。

### 按平台打包

| 命令 | 目标平台 / 架构 | 产物 |
|---|---|---|
| `npm run build:win` | Windows（默认架构） | NSIS `.exe` |
| `npm run build:win:x64` | Windows 64 位 | NSIS `.exe` |
| `npm run build:win:x86` | Windows 32 位 | NSIS `.exe` |
| `npm run build:win:arm64` | Windows ARM64 | NSIS `.exe` |
| `npm run build:mac` | macOS（当前架构） | `.dmg` |
| `npm run build:mac:intel` | macOS Intel (x64) | `.dmg` |
| `npm run build:mac:apple` | macOS Apple Silicon (arm64) | `.dmg` |
| `npm run build:mac:universal` | macOS 通用包（Intel + Apple Silicon） | `.dmg` |
| `npm run build:linux` | Linux（AppImage） | `.AppImage` |
| `npm run build:linux:deb` | Linux Debian/Ubuntu | `.deb` |
| `npm run build:linux:rpm` | Linux Fedora/RedHat | `.rpm` |

### 跨平台打包限制（重要）

| 目标 | 允许的构建机 | 说明 |
|---|---|---|
| Windows NSIS | Windows（推荐）；Linux/macOS 可交叉编译但不推荐 | NSIS 工具链 electron-builder 自带 |
| macOS dmg | **必须 macOS** | dmg 生成、签名、公证都依赖 macOS 工具链 |
| Linux AppImage | **必须 Linux**（Windows 上可用 WSL/Docker） | AppImage 打包工具不支持 Windows |

> native 模块 `better-sqlite3` 依赖 prebuild 预编译二进制；交叉架构（如 win x86/arm64）若预编译包未命中，会尝试源码编译，需要目标平台工具链，失败时优先在目标平台/架构的机器上打包。

### 在 Windows 上打 mac / Linux 包：用 GitHub Actions 云构建

Windows 本机执行 `npm run build:mac` 会报 `Build for macOS is supported only on macOS`，这是 electron-builder 硬性限制，无法本地绕过。项目已配置云构建工作流 `.github/workflows/build-desktop.yml`，推送代码到 GitHub 后：

- 打 `v*` 标签（如 `git tag v1.9.0 && git push --tags`）自动在 Windows / macOS / Ubuntu 三平台并行打包
- 也可在仓库 Actions 页面手动触发（workflow_dispatch）
- 产物（`.exe` / `.dmg` / `.AppImage`）上传为 Actions artifacts，构建完成后在页面下载

### 免安装包快速验证（推荐先跑这个）

```powershell
npm run pack          # 当前平台
npm run pack:win      # 指定 Windows
npm run pack:mac      # 指定 macOS（需在 Mac 上执行）
npm run pack:linux    # 指定 Linux（需在 Linux 上执行）
```

只构建渲染层 + `electron-builder --dir`，产出 `release/win-unpacked/`（macOS 为 `mac-arm64/`、Linux 为 `linux-unpacked/`）绿色目录，直接运行里面的可执行文件即可验证打包结果（含 native 模块是否正常），不打安装包，速度快。

### 仅构建前端

```powershell
npm run build:renderer
```

## 3. 建议的完整流程

```powershell
# 1. 确保依赖完整且 native 模块已编译
npm install

# 2. 先绿色包验证
npm run pack
#    运行 release\win-unpacked\Desktop Client.exe，确认：
#    - 能登录、消息正常
#    - 本地库可读写（本地存储功能依赖 better-sqlite3）

# 3. 验证通过后打正式安装包
npm run build
```

安装后数据目录：`%APPDATA%\desktop-client\`（storage/ 本地库、storage-config.json、backups/ 等）。

## 4. 已知问题与处理

### 4.1 打包图标（Windows / Linux 已就位）

`build/icon.ico` 已生成（256x256），源图为 `build/icon.png`（1024x1024）。Linux 打包直接使用 `build/icon.png`。

macOS 需要 `build/icon.icns`（当前缺失，缺失时使用 Electron 默认图标）。从 png 生成：

```powershell
# 在 Mac 上执行（iconutil 为 macOS 自带）
npx icon-gen -i build/icon.png -o build --icns
# 或手动：用 png 生成 iconset 目录后执行 iconutil -c icns
```

如需更换 Windows 图标：准备 256x256 及以上的 ico 覆盖 `build/icon.ico` 即可；从 png 转换：

```powershell
# 需先 npm i -D png-to-ico（或在线转换）
npx png-to-ico 你的图标.png > build/icon.ico
```

### 4.2 npm 代理导致安装失败

全局 npm 代理（127.0.0.1:7890）未启动时会 `ECONNREFUSED`，本次安装用绕过方式：

```powershell
npm install --proxy=false --https-proxy=false
```

### 4.3 native 模块 ABI 不匹配

症状：启动报 `NODE_MODULE_VERSION` 不匹配或找不到 `better_sqlite3.node`。处理：

```powershell
npm run rebuild
```

### 4.4 asar 说明

当前配置 `"asar": false`（不打包成 asar 归档），better-sqlite3 这类 native 模块可直接加载，无需 asarUnpack，保持现状即可。

### 4.5 安装器行为（NSIS 配置）

`package.json` 的 `build.nsis` 配置：

- `oneClick: false` + `allowToChangeInstallationDirectory: true`：**向导式安装，用户可自定义安装目录**（默认装到 `%LOCALAPPDATA%\Programs`，免管理员权限）
- `perMachine: false`：默认当前用户安装；如需全机器安装可改 true（需 UAC 提权）
- 自动创建桌面/开始菜单快捷方式（名称 WorkChat）；卸载不删除用户数据（聊天记录在 `%APPDATA%\desktop-client`）
- 应用内自动更新兼容自定义目录：静默安装时主进程会带上当前安装目录（NSIS `/D` 参数）覆盖安装到原位置

## 5. 运行环境提醒

- 桌面端连接的服务端地址硬编码为 `http://127.0.0.1:8080`（`src/api/http.js`）与 `ws://127.0.0.1:8080/ws`（`src/api/ws.js`），打包给其他机器使用前需改为实际服务地址再重新打包。
- 本地存储为明文 SQLite（设计文档既定第一版策略），SQLCipher 加密为后续阶段。
