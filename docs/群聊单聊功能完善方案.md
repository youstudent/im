# 群聊 / 单聊功能完善方案（对标微信）

> 版本：v1.0　日期：2026-08-20
> 关联文档：`docs/IM系统架构设计.md`、`docs/桌面端本地存储方案.md`、`docs/执行计划.md`
> 目标：以微信桌面端为参照，补齐群聊与单聊的核心交互功能，按优先级分期落地。

---

## 1. 现状盘点（已具备能力）

整理自现有代码，避免重复建设：

| 领域 | 已实现 | 位置 |
|---|---|---|
| 消息类型 | 文本/图片/文件/语音/视频/系统（1~6） | `service/internal/message`、`MainWindow.vue` MSG_TYPE |
| 收发链路 | WS 实时推送 + ack 确认 + 超时重发 + HTTP 降级 + 离线发送队列 | `ws.js`、`gateway/` |
| 撤回 | 2 分钟内撤回、"撤回了一条消息"提示、撤回后重新编辑 | `POST /conversations/:id/recall` |
| 回执 | 送达 ack、已读 read（会话级已读游标，单聊双向同步） | `sendRead/sendAck` |
| 未读 | unread_count 列维护（撤回递减，不虚高）、托盘角标 | `0009_unread_count.sql` |
| 历史 | seq 分页 + 增量拉取（afterSeq）、本地 SQLite 秒开 | `localdb`、`repos.js` |
| 搜索 | 全局/单会话聊天记录搜索（本地 + 服务端） | `SearchChatHistoryModal.vue` |
| 群管理 | 建群、邀请、退群、群名/群公告（群主/管理员鉴权）、成员上限、入群/退群系统消息按身份渲染 | `social/service.go` |
| 好友 | 申请/同意/拒绝、删除、备注（群聊内优先显示备注） | `social/handler.go` |
| 通话 | WebRTC 一对一语音通话（信令走 WS） | `api/call.js` |
| 通知 | 通知中心（好友申请/群邀请/系统）、WS 实时推送 | `NotificationCenter.vue` |

**关键缺口**（与微信的差距，本文档要解决的）：

- 会话列表：置顶、免打扰、标记未读、草稿——`conversations` 表已有 `muted/pinned` 字段但无更新接口与 UI；
- 消息交互：引用回复、@提及、多选转发/逐条转发/批量删除、逐条转发外的合并转发；
- 群管理：移除成员、设管理员、转让群主、群昵称、群禁言、入群确认、群文件面板、保存到通讯录；
- 体验细节：消息表情回应、群公告推送提醒、图片查看器等部分已有，需补齐交互。

## 3. 第一期（P0）功能详细设计

### 3.1 L1 会话置顶 + L6 排序

**交互**（对齐微信）：
- 会话项右键菜单：置顶聊天 / 取消置顶；置顶会话排成独立区块，背景浅灰；
- 排序：置顶区（内部按最后消息时间倒序）→ 普通区（按时间倒序）。

**服务端**：`conversations.pinned` 字段已存在，新增接口：

```
PUT /api/v1/conversations/:id/settings    body: { pinned?: 0|1, muted?: 0|1 }
```

- 只允许更新 owner_uid = 当前用户的会话行（鉴权防越权）；
- 返回更新后的会话 DTO；
- WS 侧不需要推送（设置是单人视角）。

**前端**：
- `api/message.js` 增加 `updateSettings(convId, {pinned, muted})`；
- 会话列表 computed 分两组渲染；右键菜单组件新增（ConversationContextMenu）；
- 本地 SQLite `conversations.pinned` 已有，写接口成功后更新本地。

### 3.2 L2 消息免打扰

**交互**：
- 右键菜单 → 消息免打扰（勾选态）；
- 免打扰会话：新消息不弹系统通知、不响铃、托盘角标不累加数字（P1 阶段改灰点，第一期先静默角标）；
- 群资料面板内也提供"消息免打扰"开关（微信在群设置里同样有）。

**实现**：同 L1 走 `PUT /conversations/:id/settings`；`ConversationDTO.muted` 已返回，前端通知逻辑（`notify.js` / `badge.js`）读取该标记跳过提醒。

### 3.3 L5/I4 草稿

**交互**：
- 切换会话时把输入框内容存为该会话草稿（纯本地，不同步服务端）；
- 会话列表最后消息位置显示红色 `[草稿] xxx`；
- 发出一条消息后清除该会话草稿。

**实现**：
- 本地 SQLite `conversations` 增加 `draft TEXT` 列（`db.js` 迁移）；
- MainWindow 切换会话 `watch(currentConvId)` 时保存/恢复；
- 草稿只在"最后一条消息时间之后未发送"场景展示，微信行为一致。

### 3.4 S1 引用回复

**交互**：
- 右键消息 → 引用；输入区上方出现引用条（发送者：内容摘要，× 可取消）；
- 发送后气泡上方带引用块（灰色小卡，显示被引用人 + 摘要）；点击引用块滚动定位到原消息；
- 被引用消息已删除/已撤回时显示"引用内容不存在"。

**协议设计**（不新增 type，走 extra，兼容现有渲染链路）：

```jsonc
// extra 增加 quote 字段
{
  "quote": {
    "msg_id": "1234567890",      // 被引用消息 id（字符串防精度丢失，与现有约定一致）
    "seq": 42,
    "sender_uid": "1001",
    "sender_name": "林晚",
    "type": 1,                    // 被引用消息类型
    "content": "原文摘要（截断 100 字）"
  }
}
```

- 服务端无需改动核心链路（extra 已透传，2KB 上限内）；仅校验 quote.msg_id 存在性可选（防伪造，P1 再收紧）；
- 本地库消息 extra 列已存 JSON，无需迁移；
- 点击定位：本地库按 msg_id 查 seq，若不在已加载区间则触发 beforeSeq 翻页加载。

### 3.5 G1 @提及

**交互**：
- 群聊输入框键入 `@` 弹出成员下拉（头像 + 群昵称/备注），支持继续输入过滤；
- 选中后插入 `@名字 `（名字用群内显示名），光标后移；@ 文本在气泡内高亮；
- 被 @ 的人：即使开了免打扰也强提醒（微信行为），通知中心"@提及"分类落地（该分类 UI 已有占位）；
- 群聊会话列表摘要显示 `[有人@我] 消息内容`（微信行为）。

**协议设计**：

```jsonc
// extra 增加 mention 字段
{ "mention_uids": ["1001", "1002"] }
```

- 发送时前端收集 @ 到的 uid 列表写入 extra；
- 服务端 `msgsToDTOs` 无需解析；推送帧原样携带 extra，接收方客户端判断 `mention_uids` 含自己 → 强提醒 + 摘要前缀；
- 被 @ 判断只在客户端做，服务端不做特殊分发（避免扩散写）。

### 3.6 G3 移除群成员

**服务端**：

```
DELETE /api/v1/groups/:gid/members/:uid
```

- 鉴权：操作者必须是群主（0）或管理员（1）；管理员不能移除群主或其他管理员（微信规则：管理员只能移除普通成员）；
- 不能移除自己（退群走已有 `DELETE /members/me`）；
- 移除后：
  1. `group_members` 删除该行；`member_count - 1`；
  2. 系统消息（kind=`group_kick`）推送全体剩余成员："你被 xx 移出群聊"（被移除者视角）/ "xx 将 yy 移出了群聊"（其他成员视角），沿用 `SendGroupSystemMessageTo` 的分身份渲染模式；
  3. 被移除者：会话标记不可再发送（发送守卫已有"非成员拒绝"），客户端收到 `group.kicked` 推送后会话置灰或移除。

**前端**：群资料面板成员网格增加"−"按钮（仅群主/管理员可见），点击弹确认框。

### 3.7 G4 设为/取消管理员

**服务端**：

```
PUT /api/v1/groups/:gid/members/:uid/role    body: { role: 1 | 2 }
```

- 仅群主可操作；role 取值 1（管理员）/ 2（普通成员），不能把管理员设为群主（转让走 G5）；
- 变更后向全体群成员推送 `group.role_changed`（客户端更新成员列表角标"管理员"标签，微信在成员头像旁有橙色"管理员"字样）；
- `group_members.role` 字段已有（AddGroupMember 第三参数），无需迁移。

**前端**：群成员列表项右键/悬浮菜单：设为管理员 / 取消管理员（仅群主可见）；管理员成员显示橙色标签。

### 3.8 I1 表情面板

- 输入区新增 😀 按钮，弹出 emoji 网格面板（分类：常用/笑脸/手势/动物/物品，纯 Unicode）；
- 点击插入到输入框光标处；面板外点击关闭；
- 纯前端实现，无服务端改动。

## 6. 数据与协议变更汇总

### 6.1 服务端迁移（新增 migrations）

```sql
-- 0012_group_enhance.sql（第二期）
ALTER TABLE group_members ADD COLUMN nickname VARCHAR(40) DEFAULT NULL COMMENT '群内昵称';
ALTER TABLE `groups` ADD COLUMN invite_confirm TINYINT NOT NULL DEFAULT 0 COMMENT '邀请需确认';
ALTER TABLE `groups` ADD COLUMN mute_all TINYINT NOT NULL DEFAULT 0 COMMENT '全员禁言';
ALTER TABLE group_members ADD COLUMN muted_until DATETIME DEFAULT NULL COMMENT '单人禁言截止';
ALTER TABLE group_members ADD COLUMN saved TINYINT NOT NULL DEFAULT 1 COMMENT '保存到通讯录';
```

第一期**无需**服务端迁移（pinned/muted/role 字段均已存在）。

### 6.2 客户端本地库迁移

```sql
-- 第一期：desktop_client/electron/store/db.js 新版本迁移
ALTER TABLE conversations ADD COLUMN draft TEXT DEFAULT NULL;
-- 第二期
ALTER TABLE conversations ADD COLUMN marked_unread INTEGER DEFAULT 0;
ALTER TABLE messages ADD COLUMN deleted INTEGER DEFAULT 0;
```

### 6.3 extra 结构化字段约定（消息 extra JSON）

| 字段 | 类型 | 引入期 | 说明 |
|---|---|---|---|
| quote | object | 一期 | 引用块 `{msg_id, seq, sender_uid, sender_name, type, content}` |
| mention_uids | string[] | 一期 | 被 @ 的成员 uid |
| merge | object | 二期 | 合并转发 `{count, items:[{sender_name, type, content}]}` |
| reaction | object | 三期 | 表情回应增量 |

> 注意 extra 有 2KB 上限（`maxExtraBytes`），quote.content 与 merge.items 需截断；合并转发条目超过限制时 content 仅存摘要、完整列表另存（二期细化）。

### 6.4 新增 HTTP 接口汇总

| 方法 | 路径 | 期次 | 说明 |
|---|---|---|---|

## 8. 风险与注意点

1. **雪花 ID 精度**：quote.msg_id、mention_uids 一律字符串传输（沿用现有约定），防 JS Number 精度丢失；
2. **撤回与引用的联动**：被引用消息被撤回/删除时，引用块降级显示"引用内容不存在"，不做级联清理（写扩散成本高）；
3. **@提及与免打扰的优先级**：被 @ 时穿透免打扰提醒，这是微信明确行为，测试需覆盖；
4. **管理员权限边界**：管理员可移除普通成员、可改群名公告（已有），但不可动群主与其他管理员（G3 鉴权务必写清）；
5. **群昵称显示优先级**：备注 > 群昵称 > 用户昵称，涉及 `friendDisplayName` 逻辑调整（现有函数仅处理备注与昵称两级）；
6. **分表影响**：消息相关新字段（deleted）需同时迁移 messages_0~3 四张分表；
7. **向后兼容**：所有 extra 新字段均可选，旧客户端忽略未知字段即可，无需强制升级。
