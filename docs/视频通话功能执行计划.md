# 桌面端视频通话功能执行计划

> 版本：v1.0　日期：2026-08-19
> 关联文档：`docs/执行计划.md`、`docs/IM系统架构设计.md`
> 前置基础：桌面端 1 对 1 语音通话已上线（WebRTC P2P + WS 信令转发），视频通话在其上扩展。

## 0. 技术栈选型

| 项 | 选型 | 说明 |
|---|---|---|
| 媒体传输 | WebRTC（Electron/Chromium 内置） | 无需引入第三方库；P2P 优先、TURN 中继兜底 |
| 视频编解码 | H.264（硬编优先）→ VP8 → VP9 | 按 SDP 能力协商；H.264 硬件加速省 CPU |
| 信令 | 复用现有 WS 网关 `call` 帧（Go） | 服务端保持纯转发不落库，改动极小 |
| NAT 穿透 | 公共 STUN（现成）+ **自建 TURN（coturn）** | 视频带宽敏感，对称 NAT 必须 TURN 兜底 |
| 音视频采集 | `navigator.mediaDevices.getUserMedia` | audio + video 约束；渲染进程调用 |
| 摄像头控制 | `enumerateDevices` + `track.enabled` / `replaceTrack` | 开/关摄像头、切换设备、静音均不重建连接 |
| 权限处理 | Electron `session.setPermissionRequestHandler` | 主进程放行 media 权限；Windows 隐私设置配合 |
| 通话 UI | Vue3 + 原生 `<video>` 元素 | 远端大窗 + 本地画中画，无额外 UI 库 |
| 通话记录 | 复用本地 SQLite 系统消息机制 | 摘要 `[视频通话]`，与语音通话同路径 |

> 关键决策：**信令层完全复用语音通话的 `invite/answer/ice/reject/busy/cancel/hangup` 动作，不新增帧类型**；只扩展帧载荷标记媒体类型（`media: "video"`）。服务端无需理解媒体细节，转发逻辑不变，风险最小。

## 1. 现状与扩展点（依据）

- 客户端：[call.js](file:///e:/vibe-coding/new_im/desktop_client/src/api/call.js) 状态机（idle → outgoing/incoming → connecting → connected → ended），当前 `getUserMedia` 仅采集音频、远端走隐藏 `<audio>` 元素。
- 通话面板：[CallWindow.vue](file:///e:/vibe-coding/new_im/desktop_client/src/components/CallWindow.vue) 全屏覆盖层，含接听/拒接/静音/挂断按钮与状态文案。
- 入口：[MainWindow.vue](file:///e:/vibe-coding/new_im/desktop_client/src/components/MainWindow.vue) 已预留视频通话按钮，但 `startVideoCall` 仅提示"暂未开放"。
- 服务端：[call.go](file:///e:/vibe-coding/new_im/service/internal/gateway/call.go) 纯信令转发 + `busy.set/busy.clear` 忙线维护 + 离线代答 + 好友校验；**载荷上限 32KB**（视频 SDP 可能超限，需提升）。
- 网络：ICE 仅配置公共 STUN，**无 TURN**（语音可容忍打洞失败，视频不可容忍）。
- 权限：Electron 主进程**未配置** media 权限处理器（视频必须补，否则打包环境取不到摄像头）。

## 2. 里程碑总览

| 阶段 | 名称 | 完成标志 |
|---|---|---|
| P0 | 技术预研 | 打包环境可采集摄像头；确认视频 SDP 体积；选定编解码优先级 |
| P1 | 信令与协议扩展 | 服务端透传 `media` 字段、载荷上限提升、单测通过 |
| P2 | 客户端视频通话核心 | 双端可接通视频、画面互看、静音/挂断可用 |
| P3 | TURN 部署与穿透 | coturn 上线，跨网（对称 NAT）可接通 |
| P4 | 体验与容错 | 摄像头开关/切换、弱网提示、来电通知、通话记录文案 |
| P5 | 测试与验收 | 端到端脚本 + 人工清单全过，语音通话无回归 |

> 依赖：P1 依赖 P0（SDP 体积决定上限取值）；P2 依赖 P1；P3 可与 P2 并行；P4 依赖 P2；P5 依赖全部。

## 3. 分阶段执行计划

### P0 技术预研（0.5 天）

目标：消除两个不确定点——Electron 摄像头权限、视频 SDP 体积。

1. **摄像头采集验证**：在 Electron 渲染进程调用 `getUserMedia({ video: { width: 1280, height: 720 } })`。
   - 若失败：在主进程加 `session.setPermissionRequestHandler`（对 media 请求放行）+ `setPermissionCheckHandler`；同时确认 Windows 系统"摄像头隐私设置"允许桌面应用访问。
   - 记录 Electron 下 `videoinput` 设备枚举（`enumerateDevices`）结果，验证无设备时的报错形态（决定降级 UI 文案）。
2. **SDP 体积测量**：`createOffer` 后打印 `pc.localDescription.sdp.length`，分别测 H.264/VP8/VP9 组合与 720p/1080p 约束下的体积，确认是否超过服务端 `callPayloadMaxLen`（32KB）。
3. **编解码优先级结论**：用 `RTCRtpSender.getCapabilities('video')` 探测，确定 offer 编解码顺序（优先 H.264，若打包 Chromium 无 H.264 则 VP8 兜底）。

产出：权限处理代码雏形、SDP 体积实测数据、编解码优先级结论。

### P1 信令与协议扩展（1 天，服务端）

1. `call.go`：
   - 帧载荷增加 `media` 字段（`"audio"` / `"video"`），校验合法取值；对旧客户端缺省按 `"audio"` 兼容。
   - `callPayloadMaxLen` 按 P0 实测上调（预计 64KB~128KB），与 WS `SetReadLimit(128KB)` 对齐；注释说明视频 SDP 场景。
2. 单测补充（`call_test.go`）：
   - `media: "video"` 帧正常透传、`from` 仍被覆写为真实 uid；
   - 非法 `media` 值 / 超长载荷被拒绝不转发；
   - 忙线、离线代答对 video 帧行为与语音一致（复用现有用例参数化）。
3. 回归：现有 7 个语音单测全过。

验收：`go test ./internal/gateway/` 全绿；视频信令走通离线/忙线/好友校验分支。

### P2 客户端视频通话核心（2~3 天，desktop_client）

1. `src/api/call.js`：
   - 新增 `startVideoCall(peer)`（与 `startCall` 同构）：`getUserMedia({ audio: {...}, video: { width: { ideal: 1280 }, height: { ideal: 720 }, facingMode: 'user' } })`；摄像头失败时**降级**：提示后仅以音频继续或直接结束（决策：默认降级为语音通话并 toast 说明，用户可接受）。
   - `callState` 增加 `media`（audio/video）、`cameraOn`（布尔）；信令帧统一带 `media` 字段。
   - `ontrack`：按轨道类型分流——`video` 轨挂到远端 `<video>`，`audio` 轨挂 `<audio>`；双轨共用一个 MediaStream 时统一挂到 video 元素（自动包含音频）。
   - 新增 `toggleCamera()`（`videoTrack.enabled` 翻转，画面变黑但连接保持）与 `switchCamera()`（`enumerateDevices` 取 `videoinput` 列表 → `replaceTrack` 或重建 SDP，无需重协商则优先 `replaceTrack`）。
   - 清理逻辑：结束通话时 `stopLocalStream` 同时停视频轨；`remoteVideo.srcObject = null`。
2. `src/components/CallWindow.vue`：
   - 布局改造：通话中显示远端大视频（`object-fit: cover` 黑底）+ 本地画中画小窗（右下角，`muted` 预览、可拖动置顶不置顶）；来电/拨出阶段仍显示头像 + "视频通话"文案。
   - 按钮区：`connected` 态增加"开/关摄像头"（与静音并列）与"切换摄像头"（多设备时才显示）；来电文案区分"视频通话"/"语音通话"。
   - 通知：来电系统通知标题/正文标注"视频通话"。
3. `src/components/MainWindow.vue`：`startVideoCall` 去掉占位 toast，接线到 `startVideoCall(peer)`；拨号来源补充摄像头按钮（会话头部视频通话按钮）。
4. Electron 主进程：P0 权限代码正式落地（放行 `media`，其余权限维持拒绝）。

验收：同机双窗口/双账号互拨可互看画面、声音正常；静音、挂断、取消、拒绝、忙线、离线各分支与语音一致；关摄像头后画面黑但通话不中断。

### P3 TURN 部署与穿透（1~2 天，独立于 P2 可并行）

1. **部署 coturn**：`service/docker-compose.yml` 增补 coturn 服务（或独立服务器），配置：
   - `listening-port=3478`、`tls-listening-port=5349`（可选）；
   - 静态凭据 `static-auth-secret` 或 `user=`，`realm` 固定；
   - UDP/TCP relay 端口区间，防火墙放行；
   - `min-port/max-port` 限制中继端口范围（带宽与安全考量）。
2. **客户端配置**：`call.js` 的 `ICE_SERVERS` 追加 TURN（含凭据），保留现有公共 STUN。
3. **验证**：两账号分别处于对称 NAT（如不同运营商 4G 热点）环境互拨；Chrome `chrome://webrtc-internals` 查看 ICE candidate 是否落到 `relay` 类型。
4. 补充：说明 TURN 中继带宽成本（视频约 0.5~2Mbps/路，按并发预估带宽），在配置注释中给出扩容建议。

验收：跨对称 NAT 视频通话可建立；`relay` 候选可联通；语音通话不受影响。

### P4 体验与容错（1~2 天）

1. **弱网处理**：`onconnectionstatechange` 中 `disconnected` 显示"网络不稳定，通话可能中断"浮层；`failed` 结束并提示（与语音现有逻辑一致）。
2. **带宽自适应**：依赖 WebRTC 内建拥塞控制（Transport-CC/REMB），默认 720p；不引入额外库。如实测带宽波动明显，可加 `RTCRtpSender.setParameters` 限制 `maxBitrate`。
3. **通话记录**：结束回调落库文案 `[视频通话]`（与 `[语音通话]` 同机制，`server_id` 带 `call-` 前缀、`sender_uid=0`、本地 seq=0 记录）。
4. **权限与设备异常**：首次无摄像头/权限拒绝 → 降级语音并提示；通话中拔掉摄像头 → 自动切 `track.enabled=false` 并 toast；设备恢复不自动重连（提示手动切换）。
5. **切窗联动**（可选）：通话期间窗口最小化/失焦保持画面，不额外处理。

验收：断网/弱网提示符合预期；通话记录显示 `[视频通话]`；无摄像头设备可正常降级语音。

### P5 测试与验收（1 天）

1. **服务端**：`go test ./internal/gateway/` 全绿（含新增视频信令用例）。
2. **端到端脚本**：仿 `scripts/test_voice_call.mjs` 新增 `scripts/test_video_call.mjs`，覆盖：
   - video invite/answer/ice 透传与 `media` 字段完整性；
   - 离线代答、忙线代答、好友校验拦截（复用语音场景）；
   - 超长 payload 被拒。
3. **人工验收清单**（双实例 + 跨网各一轮）：
   - 视频接通/挂断/拒绝/取消/忙线/离线；
   - 静音、关摄像头、切换摄像头；
   - 本地画中画与远端画面方向正确；
   - 来电通知、通话记录 `[视频通话]`；
   - 无摄像头/权限拒绝降级语音；
   - 语音通话全功能回归无破坏。

## 4. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 对称 NAT 打洞失败 | 视频完全无法接通 | P3 自建 TURN 兜底；ICE 候选类型纳入验收项 |
| 视频 SDP 超 32KB 被服务端丢弃 | 邀请静默失败 | P0 实测体积 → P1 上调载荷上限并补单测 |
| Electron 拿不到摄像头 | 无法采集 | P0 权限处理先行；Windows 隐私设置在文档中给出排查指引 |
| 摄像头被占用（其他应用） | 采集失败 | 降级语音 + 明确提示文案 |
| TURN 带宽成本增长 | 服务器流量开销 | relay 端口与账号限流；配置注释给出扩容建议 |
| 视频推流拉高 CPU | 低配机器卡顿 | 默认 720p + H.264 硬编优先；不启用 simulcast |
