# 桌面端本地存储方案设计

> 版本：v1.0　日期：2026-08-13
> 范围：`desktop_client`（Electron + Vue3）
> 目标：为桌面端引入本地持久化，实现离线可用、秒开、省流量、数据可导出/备份/清理。

---

## 1. 定位与目标

当前桌面端数据全部在内存 mock 中，仅主题/字体/存储路径三处用了 `localStorage`。引入本地存储后要达到：

| 目标 | 说明 |
|---|---|
| 离线可用 | 无网/弱网时能浏览历史消息、会话列表、联系人 |
| 秒开 | 启动时从本地库直接渲染，不等网络 |
| 省流量/省服务端压力 | 历史消息本地缓存，只做增量同步 |
| 数据归属 | 聊天记录/文件落在本地，可导出、备份、清理（对应设置项） |
| 安全 | Token 与本地数据加密，避免明文落盘 |

---

## 2. 技术选型

| 项 | 选型 | 理由 |
|---|---|---|
| 本地数据库 | **SQLite + better-sqlite3-multiple-ciphers** | Electron 桌面端标准选择；better-sqlite3 的加密 fork（API 兼容），内置 SQLite3MultipleCiphers/SQLCipher，同步 API 简单、性能好、单文件、零运维 |
| 访问方式 | **主进程持有连接 + IPC** | 渲染进程经 preload 调领域 API，不暴露 Node/原始 SQL，符合现有 `contextIsolation` 规范 |
| UI 偏好 | localStorage（沿用） | 主题/字体需首屏同步，现有机制已可用，不迁移 |
| 加密 | Electron `safeStorage` + SQLCipher（已实施） | Token 用 safeStorage 加密；数据库用 **SQLCipher 全库加密**（每账户随机密钥，safeStorage 保管） |
| 文件缓存 | 本地目录（`files/`、`cache/`） | 图片/文件/语音落本地，命中直接读，不再重复下载 |

> `better-sqlite3-multiple-ciphers` 为 native 模块，按 Electron ABI 从 GitHub Releases 下载 prebuild（支持 Electron v29–v42），`electron-builder install-app-deps`（postinstall）自动处理；无预编译时才需源码编译。注意：**v13+ 已放弃 Electron 35 以下支持，本项目锁定 12.11.1**。

---

## 3. 存储分层（三类数据三套策略）

| 层 | 载体 | 内容 | 策略 |
|---|---|---|---|
| UI 偏好 | localStorage | 主题、字体大小、语言 | 沿用现有，秒同步首屏 |
| 业务数据 | SQLite（`workchat.db`） | 消息、会话、联系人、群、通知、同步游标 | 主进程访问，离线可用 |
| 文件数据 | 本地目录 | 图片/文件/语音缓存、备份、临时缓存 | 按需下载、可清理 |

---

## 4. 本地目录结构

存储根目录 `storagePath`（默认 `app.getPath('userData')`，可在设置里改，前端已有 `selectDirectory`）：

```
{storagePath}/
├── workchat.db          # SQLite 主库（业务数据）
├── files/               # 文件缓存（图片/文件/语音）
│   └── {sha256[:2]}/{sha256}.{ext}
├── cache/               # 临时缓存（可安全清理）
└── backups/             # 聊天记录备份
```

- `files/` 用内容哈希命名，天然去重（同一文件多处引用只存一份）。
- `cache/` 与 `backups/` 分开，清理时只动 `cache/`，不影响正式数据。

---

## 5. SQLite 表设计（本地投影 + 同步字段）

本地表是服务端 schema 的**投影**，并增加同步状态字段，实现离线队列与增量拉取：

| 表 | 用途 | 关键增量字段 |
|---|---|---|
| `users` | 自己 + 联系人资料缓存 | — |
| `conversations` | 会话列表 | `last_synced_seq`（增量拉取游标） |
| `messages` | 消息 | `sync_state`（pending/synced/failed，离线发送队列） |
| `groups` / `group_members` | 群缓存 | — |
| `notifications` | 通知 | `read` |
| `kv` | 元数据（schema 版本、同步游标、清理标记） | — |

字段与 `docs/IM系统架构设计.md` 第 6 节服务端 schema 对齐，直接映射前端 mock 的 `id/name/avatar/unread/lastMessage/type/text/readAt` 等。

---

## 6. 同步策略（离线优先）

```
启动 → 读本地库渲染(秒开) → 后台连服务端
  → 增量拉取：拉 > last_synced_seq 的消息 / 会话 / 联系人
  → 实时：WebSocket 推送同时写本地库
```

- **发送**：先写本地 `messages(sync_state=pending)` 乐观展示 → 发送成功回填 `server_id`、置 `synced` → 失败置 `failed` 可重试。
- **历史消息**：按会话 `last_synced_seq` 增量拉取；下拉翻页时向前补拉。
- **已读/未读**：本地维护计数，服务端校准；重连后以服务端为准。
- **联系人/群**：启动全量刷新一次，之后走推送增量。

## 7. 加密方案

| 数据 | 方案 |
|---|---|
| Token | Electron `safeStorage.encryptString`（系统级加密，前端已有基础） |
| 数据库 | **SQLCipher 全库加密（已实施）**：better-sqlite3-multiple-ciphers 驱动 + `PRAGMA cipher='sqlcipher'`；每账户随机 32 字节密钥，safeStorage 加密后存 `{userData}/db-keyring.json`（密钥与数据分离，存储路径迁移不受影响）；存量明文库启动时自动就地迁移（原文件保留 `.plain.bak` 兜底） |
| 敏感字段 | 全库加密已覆盖消息正文，无需额外字段级加密 |
| 文件缓存 | 不加密（量大、非敏感）；敏感聊天记录可选「不缓存到本地」开关 |

> 密钥丢失（userData 被清）时加密库不可恢复：本地库定位为缓存，删除 `accounts/{uid}` 重建后从服务端重新同步即可，不阻断使用。

## 8. 承接前端「数据存储」设置项

| 设置项（前端已画） | 本地存储实现 |
|---|---|
| 本地存储位置 | `storagePath` 作为 DB + files 根目录（已有 `selectDirectory`，改动路径时迁移/重建索引） |
| 消息保留时长 | 后台定时任务按 `messages.created_at` 删除超期消息（默认永久） |
| 自动清理缓存 | 定时清理 `cache/` 目录（保留时长/大小阈值） |
| 缓存占用 | 实时统计 `workchat.db` + `files/` + `cache/` 大小，替换静态「1.2 GB」 |
| 导出聊天记录 | 从 SQLite 读消息 → 生成 HTML / TXT 文件（含图片路径） |
| 聊天记录备份 | 复制/导出 `workchat.db` 到 `backups/` 或指定文件夹，支持定期 |

## 9. IPC 扩展（preload 新增接口）

沿用现有 `preload.js` 模式，向渲染进程暴露**领域方法**（不暴露原始 SQL/Node）：

```js
window.store = {
  // 消息/会话/联系人/通知（渲染进程只调用这些）
  conversations: { list, get, setMuted },
  messages:     { list, append, markRead, pending, sync },
  contacts:     { list, get },
  notifications:{ list, markRead, markAllRead },
  // 设置与元数据
  settings:     { get, set },
  // 文件与存储
  storage:      { getPath, setPath, getUsage, clearCache },
  export:       { toHtml, toTxt },
  backup:       { create, restore },
}
```

主进程侧对应实现 `ipcMain.handle`，SQLite 访问集中在「存储访问层」，导出/备份/清理为独立模块。

## 11. 与服务端的关系

- 本地库是**缓存 + 离线队列**，服务端仍是唯一事实源（source of truth）。
- 本地库可随时删除重建（重建后从服务端重新同步），因此不承载任何不可再生数据。
- 冲突以服务端为准：重连/刷新时服务端数据覆盖本地未同步状态。
