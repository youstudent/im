## 3. 主进程存储访问层

新建目录 `desktop_client/electron/store/`，包含三个模块。

### 3.1 db.js — 连接、会话与迁移

**目录结构（按账户物理隔离）**：

```
{userData}/storage/
└── accounts/
    ├── {uid_A}/workchat.db   # 账户 A 的独立数据库
    └── {uid_B}/workchat.db   # 账户 B 的独立数据库
```

- 每个登录账户一个独立数据库文件，互不可见；这是多账户隔离的主手段（文件级隔离，任何查询都不可能跨账户串数据）。
- 第一版存储根目录固定为 `userData/storage`；设置页「更改存储位置」的迁移能力留待下阶段。
- **会话管理（单活连接）**：主进程同一时刻只持有一个账户的 DB 句柄：
  - `openSession(uid)`：关闭当前句柄 → 打开（或首次创建）`accounts/{uid}/workchat.db` → 执行迁移。
  - `closeSession()`：登出/被踢/应用退出时关闭句柄；文件保留在磁盘。
  - `db.pragma('journal_mode = WAL')`；`app.on('will-quit')` 时 `closeSession()`。
- **安全原则**：渲染进程调用数据接口时不传 owner_uid，由主进程一律作用于当前会话账户的库；会话未打开时所有数据接口返回空/拒绝，杜绝写错账户。
- 用 `kv` 表的 `schema_version` 做版本迁移（每个账户库独立迁移），第一版 schema：

```sql
CREATE TABLE kv (
  key   TEXT PRIMARY KEY,
  value TEXT
);

CREATE TABLE conversations (
  id              TEXT PRIMARY KEY,         -- 服务端 conv_id（雪花 ID，字符串防精度丢失）
  owner_uid       TEXT NOT NULL,            -- 归属用户 uid（文件级隔离为主，此字段做一致性自检/导出标识）
  type            INTEGER,                  -- 1 单聊 / 2 群聊
  target_id       TEXT,
  last_msg        TEXT,                     -- 最后消息摘要
  last_msg_time   INTEGER DEFAULT 0,        -- unix 秒
  unread          INTEGER DEFAULT 0,
  last_synced_seq INTEGER DEFAULT 0,        -- 增量拉取游标
  peer_read_seq   INTEGER DEFAULT 0,        -- 对端已读游标（单聊）
  muted           INTEGER DEFAULT 0,
  pinned          INTEGER DEFAULT 0
);
CREATE INDEX idx_conv_owner ON conversations(owner_uid);

CREATE TABLE messages (
  local_id   INTEGER PRIMARY KEY AUTOINCREMENT,
  server_id  TEXT,                          -- 服务端消息 id；离线发送暂存时为空
  conv_id    TEXT NOT NULL,
  seq        INTEGER DEFAULT 0,             -- 会话内序号（服务端分配）
  sender_uid TEXT,
  sender_name TEXT,
  type       INTEGER,                       -- 1 文本 / 2 图片 / 3 文件 / 6 系统
  content    TEXT,
  extra      TEXT,                          -- JSON 字符串（图片/文件元数据）
  status     INTEGER DEFAULT 0,             -- 0 正常 / 1 已撤回
  created_at INTEGER,                       -- unix 秒
  sync_state TEXT NOT NULL DEFAULT 'synced', -- pending / synced / failed
  UNIQUE(conv_id, server_id)
);
CREATE INDEX idx_msg_conv_seq ON messages(conv_id, seq);
```

> 表结构为服务端 schema 的本地投影，与 `service/migrations/0001_init.sql`、`0002_conversations.sql` 字段对齐；本地不分表，额外增加 `sync_state` 承载离线队列。

### 3.2 repos.js — 仓储层（prepared statements）

- `conversationRepo`
  - `listByOwner(ownerUid)`：按 `last_msg_time` 倒序。
  - `upsertMany(ownerUid, convs)`：`INSERT ... ON CONFLICT(id) DO UPDATE`，服务端字段覆盖本地，`unread` 以服务端值为准。
  - `bumpLastMessage(convId, lastMsg, lastMsgTime)`：收到新消息时更新摘要/时间，未读 +1。
  - `setUnread(convId, n)`、`updateSyncSeq(convId, seq)`。
- `messageRepo`
  - `listByConv(convId, { beforeSeq, limit })`：升序返回；`beforeSeq` 用于向上翻页。
  - `upsertMany(messages)`：按 `conv_id + server_id` 去重（INSERT OR REPLACE），网络拉取与 WS 推送统一入口。
  - `appendPending(msg)`：离线发送先落 `sync_state = 'pending'`。
  - `setSyncState(localId, state, { serverId, seq })`：成功回填服务端 id/seq 置 synced；失败置 failed。
  - `listPending(ownerUid)`：重连后取离线队列。

### 3.3 ipc.js — ipcMain.handle 注册

命名空间 `store:*`，入参做类型校验，返回纯 JSON：

| Channel | 说明 |
|---|---|
| `store:session:open` | 登录后打开该账户的库（入参 uid） |
| `store:session:close` | 登出/被踢时关闭当前库 |
| `store:session:current` | 返回当前会话 uid（未打开为 null） |
| `store:conversations:list` | 列当前账户会话 |
| `store:conversations:upsert` | 批量 upsert 会话 |
| `store:conversations:bump` | 更新摘要/未读 |
| `store:conversations:set-unread` | 清零/设置未读 |
| `store:messages:list` | 会话历史（分页） |
| `store:messages:upsert` | 批量写入（网络/WS） |
| `store:messages:append-pending` | 离线发送入队 |
| `store:messages:set-sync-state` | 回填同步状态 |
| `store:messages:list-pending` | 取离线队列 |
| `store:kv:get` / `store:kv:set` | 元数据 |
| `store:meta:path` | 返回存储根目录（设置页展示） |

在 `electron/main.js` 中 `require('./store/ipc').register()`，并在 `will-quit` 关闭会话。

### 3.4 多账户隔离与切换设计

**为什么按账户独立建库（而非同库 owner_uid 分区）**：

1. 文件级物理隔离，不依赖每条 SQL 都正确带 owner 过滤，零串号风险；
2. 登出清理、单账户数据删除、备份/导出（后续阶段）均以目录为单位，实现简单；
3. 与微信/钉钉类客户端的按账户目录组织方式一致。

**登录切换生命周期**（对接 `src/App.vue` 现有流程）：

| 时机 | 动作 |
|---|---|
| 登录成功（App.vue 写入 `workchat:me` 处） | `session.open(user.uid)`，随后 MainWindow 直接读本地库秒开 |
| 主动退出登录（`handleLogout`） | `session.close()`；DB 文件保留，下次登录同一账户仍秒开 |
| 登录失效/被踢（`auth:expired` 清空 `workchat:me` 处） | 同样 `session.close()`，防止旧会话继续写入 |
| 应用退出 | `will-quit` → `closeSession()` |

**数据归属规则**：

- 会话、消息、未读计数、离线发送队列（pending）、同步游标全部落在账户自己的库内，切换账户即切换库，天然互不可见。
- 登出默认**保留**本地数据（再次登录秒开）；服务端仍是事实源，删除 `accounts/{uid}/` 目录即彻底清除该账户本地痕迹。
- localStorage 中的 `workchat:me`、好友/群缓存（social.js）也属于账户相关数据：登出时一并清理（`workchat:me` 现有逻辑已清；好友/群缓存补充清理），避免 B 账户看到 A 账户缓存的联系人。
- UI 偏好（主题/字体）与账户无关，继续留在全局 localStorage。

## 4. preload 暴露 window.store

`electron/preload.js` 中经 contextBridge 新增独立命名空间 `window.store`（不动现有 `electronAPI`）：

```js
window.store = {
  session:       { open, close, current },
  conversations: { list, upsert, bump, setUnread },
  messages:      { list, upsert, appendPending, setSyncState, listPending },
  kv:            { get, set },
  meta:          { getPath },
}
```

全部走 `ipcRenderer.invoke`，不暴露原始 SQL / Node 能力，符合现有 contextIsolation 规范。

## 5. 渲染进程封装

新建 `desktop_client/src/api/localdb.js`：

- 统一判空封装：`window.store` 不存在（浏览器调试 / 无 Electron 环境）时所有方法降级为 no-op / 空数组，保证现有逻辑不崩。
- `available()` 探测能力是否可用。
- 雪花 ID 一律字符串化后传递（与服务端交互约定一致）。
- `session.open(uid)` 幂等：重复打开同一 uid 不重建连接；`current()` 供调用前自检。

## 6. MainWindow 接入离线优先

修改 `src/components/MainWindow.vue`，保持最小侵入，复用现有 `loadRealData / loadConversationMessages / sendMessage / onWsMessage`：

1. **登录开库**：`App.vue` 登录成功写入 `workchat:me` 后调用 `localdb.session.open(user.uid)`；`handleLogout` 与登录失效清理处调用 `localdb.session.close()`（含好友/群 localStorage 缓存清理）。
2. **秒开渲染**：`loadRealData()` 开头先经 localdb 读本地 conversations（作用于当前会话账户的库，无需传 uid）立即填充 `conversations.value` 并置 `useRealBackend = true`；随后网络拉取成功则 upsert 本地库并以后端为准刷新列表；网络失败（catch 分支）保留本地数据渲染（离线可用），不再退回 mock。
3. **历史消息本地优先**：`loadConversationMessages()` 先读本地 messages 渲染，再走 `messageApi.getHistory` 拉取 → upsert 本地库 → 用合并去重后的结果刷新（以 server_id/seq 去重）；网络失败保留本地结果。向上翻页（prepend）同样先查本地 `beforeSeq`。
4. **乐观发送落库**：`sendMessage()` 中乐观消息先 `appendPending`（sync_state=pending）；HTTP 兜底成功 → `setSyncState(synced)` 回填 server_id/seq；WS 发送以 ack / `onWsMessage` 回包确认后置 synced；失败置 failed（界面已有「发送失败」文案）。
5. **WS 推送落库**：`onWsMessage` 收到 `msg.push` 时 `messages.upsert` + `conversations.bump`（更新摘要/时间/未读）。
6. **离线队列重发**：WS 重连成功（`status` 变为 connected）时取 `listPending`，逐条经 `wsClient.sendMessage` 重发。
7. **已读游标持久化**：`peer_read_seq` 随 conversations 一并落库，`readCursorMap` 初始化时优先读本地。

## 7. 测试计划

1. **编译验证**：`npm install` 后确认 better-sqlite3 针对 Electron ABI 编译成功；`npm run dev` 启动无报错。
2. **正常流程**：登录 → 会话/消息渲染 → 检查 `{userData}/storage/accounts/{uid}/workchat.db` 已写入数据。
3. **秒开/离线**：停掉 Go 服务重启应用，会话列表与历史消息仍可从本地渲染。
4. **离线发送**：断网发消息 → 显示发送中/失败标记且写入 pending；恢复网络重连后自动重发并置 synced。
5. **去重正确**：多次拉取/多端收消息后，本地 messages 无重复（conv_id + server_id 去重）。
6. **降级验证**：纯浏览器环境（`npm run preview`）下 localdb 全部 no-op，功能回退到现有纯网络模式不报错。
7. **多账户切换**：账户 A 登录并产生本地数据 → 退出登录 → 登录账户 B，确认 B 看不到 A 的会话/消息/未读/联系人缓存，且 B 的本地库位于独立目录；退出 B 重新登录 A，确认 A 的本地数据恢复秒开；断网切回 A 时离线数据仍属 A。
8. **异常路径**：被踢下线/令牌失效后确认会话已关闭，期间收到的推送不再写入旧账户库。

## 8. 假设与约束

- 第一版数据库明文存储（设计文档既定策略），依赖系统目录权限；SQLCipher 为后续进阶项。
- 存储路径第一版固定为 `userData/storage`；设置页「本地存储位置」的实际迁移能力下阶段实现。
- 服务端仍是唯一事实源（source of truth）；本地库可随时删除重建，不承载不可再生数据。
- mock 兜底逻辑仅在本地库与后端都不可用时保留，行为不变。
- 多账户隔离以「按账户独立数据库文件」为准；登出默认保留本地数据以支持秒开，彻底清除通过删除对应账户目录完成（设置页「清除本账户数据」按钮留待后续阶段）。
