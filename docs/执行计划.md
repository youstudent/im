# IM 系统落地执行计划

> 版本：v1.0　日期：2026-08-13
> 关联文档：`docs/IM系统架构设计.md`、`docs/桌面端本地存储方案.md`

## 0. 已确定的技术决策（执行前提）

| 项 | 决策 |
|---|---|
| 服务端 | Go + Gin（框架可换 Kratos） |
| 数据库 | MySQL 8.0（关系数据）、Redis（在线/未读/路由/缓存） |
| 对象存储 | 阿里云 OSS |
| 桌面端本地存储 | SQLite + better-sqlite3（主进程 + IPC） |
| 管理后台 | Vue3 + Vite + Element Plus |
| 明确不用 | 短信验证码、Elasticsearch、消息队列（Kafka/RabbitMQ）、服务发现、配置中心 |

## 2. 目录结构约定

### 2.1 service（Go）

```
service/
├── go.mod / go.sum
├── Makefile                      # build / run / migrate 命令

├── cmd/server/main.go            # 启动入口（HTTP + WS）
├── internal/
│   ├── config/                   # 配置加载

│   ├── gateway/                  # WebSocket 网关（连接/心跳/鉴权/路由）
│   ├── auth/                     # 认证（注册/登录/JWT/二维码）
│   ├── user/                     # 用户/好友
│   ├── message/                  # 消息（收发/历史/已读/未读）
│   ├── group/                    # 群组
│   ├── notify/                   # 通知
│   ├── file/                     # 文件/OSS
│   ├── search/                   # 消息搜索
│   ├── store/                    # 数据访问层
│   │   ├── mysql/                # 迁移 + DAO
│   │   ├── redis/                # 在线/未读/路由
│   │   └── oss/                  # 阿里云 OSS
│   └── pkg/                      # jwt / snowflake / resp / err / log
├── migrations/                   # SQL 迁移文件
└── docker-compose.yml            # mysql + redis（本地）
```

## 5. 关键风险与注意点

1. **better-sqlite3 是 native 模块**：需与 Electron ABI 匹配，打包时 `electron-rebuild`；开发期用 `electron` 命令跑以对齐 ABI。
2. **消息可靠性是主线**：`msgId` 去重 + `seq` 有序 + ACK 补发要尽早打牢，否则后续类型/群聊都会埋坑。
3. **本地库是缓存不是事实源**：任何同步冲突以服务端为准，本地库可删除重建。
4. **二维码登录依赖手机端**：阶段二可先做「生成+轮询」闭环，真实扫码等手机 App 就绪再联调，桌面端接口先打通。
5. **OSS 依赖阿里云**：本地与生产统一用阿里云 OSS，需配置 AccessKey/SecretKey，密钥只放本地 `config.yaml`（不入代码库）。
6. **Go 依赖网络**：首次 `go mod download` 需可访问代理（可配 GOPROXY）。
7. **阶段三范围最大**：建议拆小步（先单机同进程收发跑通，再拆网关多实例 + Redis 路由），避免一次做太重。

## 6. 建议的启动顺序

1. 先做阶段一 + 阶段二，把「能登录」跑通，同时并行搭桌面端本地存储层（阶段三 3.1）。
2. 再集中攻克阶段三消息核心（先单机同进程收发，后拆网关多实例）。
3. 之后按四 → 五 → 六推进，阶段四/五有部分可并行（好友与群文件、搜索可并行开发）。
