## 3. 关键设计决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| Feed 模式 | **拉模式（pull）**：读时按好友列表查 posts | 好友量级小（IM 场景，非微博大 V），免维护 fanout 写扩散表，实现简单一致；后期好友动态量大再引入 Redis 缓存/推模式 |
| 互动可见性 | **共同好友规则**：查看者须同时是作者与互动者的好友才可见其点赞/评论 | 对齐微信；服务端在组装 DTO 时按查看者好友集合过滤 |
| 图片存储 | OSS 预签名直传，posts.media 存 JSON 数组（object_key + 尺寸） | 复用现有 file 链路；展示 URL 由服务端签发（预签名 URL 会过期，参考 message 模块 OSSSigner 刷新做法） |
| 删除语义 | posts.status 软删除（0 正常 / 1 已删除），物理数据保留便于审计 | 对齐消息撤回的软删风格 |
| 通知 | 点赞/评论写 notifications 表（type=`moment`）+ WS `social` 事件 `moment.interaction` | 复用通知中心，不新建通知体系 |
| ID | 雪花 ID，前端以字符串传输 | 对齐 MessageDTO 的 `json:"id,string"` 约定 |

## 4. 数据库设计

新增迁移 `service/migrations/0013_moments.sql`：

```sql
-- 朋友圈动态
CREATE TABLE IF NOT EXISTS moments_posts (
    id         BIGINT       NOT NULL COMMENT '动态 ID（雪花）',
    uid        BIGINT       NOT NULL COMMENT '发布者',
    content    VARCHAR(2000) NOT NULL DEFAULT '' COMMENT '文字内容',
    media      JSON         DEFAULT NULL COMMENT '图片数组 [{object_key,width,height}]，最多 9 张',
    visibility TINYINT      NOT NULL DEFAULT 0 COMMENT '0 好友可见 / 1 仅自己可见',
    status     TINYINT      NOT NULL DEFAULT 0 COMMENT '0 正常 / 1 已删除',
    created_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    KEY idx_uid_time (uid, created_at),   -- 个人主页 / 作者维度拉取
    KEY idx_time (created_at)              -- 全局时间线
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='朋友圈动态';

-- 点赞：(post, uid) 唯一
CREATE TABLE IF NOT EXISTS moment_likes (
    moment_id  BIGINT   NOT NULL,
    uid        BIGINT   NOT NULL COMMENT '点赞者',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (moment_id, uid)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='朋友圈点赞';

-- 评论
CREATE TABLE IF NOT EXISTS moment_comments (
    id         BIGINT       NOT NULL COMMENT '评论 ID（雪花）',
    moment_id  BIGINT       NOT NULL,
    uid        BIGINT       NOT NULL COMMENT '评论者',
    reply_uid  BIGINT       DEFAULT NULL COMMENT '被回复者（回复某条评论时）',
    content    VARCHAR(1000) NOT NULL,
    created_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    KEY idx_moment (moment_id, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='朋友圈评论';
```

> 游标分页使用 `(created_at, id)` 双字段游标（created_at 可能同秒重复，id 兜底保证稳定翻页）。

## 5. API 设计

路由前缀 `/api/v1/moments`，全部走 `middleware.JWT`，注册于 `internal/server/router.go`。

| 方法 | 路径 | 说明 | 关键参数 / 返回 |
|---|---|---|---|
| POST | `/moments` | 发布动态 | `{content, media:[{object_key,width,height}], visibility}` → PostDTO |
| GET | `/moments` | 时间线（自己 + 好友） | `cursor`（上页最后一条的 `created_at,id`）、`limit`（默认 10，上限 20）→ `{items:[PostDTO], next_cursor}` |
| GET | `/moments/user/:uid` | 某人发布的动态 | 校验好友关系（本人除外）；同上游标分页 |
| DELETE | `/moments/:id` | 删除自己的动态 | 仅作者；软删 |
| POST | `/moments/:id/like` | 点赞 | 幂等（INSERT IGNORE） |
| DELETE | `/moments/:id/like` | 取消点赞 | |
| POST | `/moments/:id/comments` | 评论 | `{content, reply_uid?}` → CommentDTO |
| DELETE | `/moments/:id/comments/:cid` | 删除评论 | 仅评论作者（P1：动态作者也可删） |

**PostDTO**（互动区已按查看者过滤）：

```json
{
  "id": "1834...", "uid": 1001, "nickname": "林一", "avatar": "...",
  "content": "今天天气不错", "visibility": 0,
  "media": [{"url": "https://oss.../signed", "width": 1080, "height": 720}],
  "likes": [{"uid": 1002, "nickname": "备注名"}],
  "comments": [{"id": "...", "uid": 1002, "nickname": "...", "reply_uid": null, "reply_nickname": null, "content": "...", "created_at": 1787...}],
  "liked": false, "created_at": 1787...
}
```

**服务端组装规则**：
1. 拉取候选动态：`SELECT ... WHERE (uid = 我 OR uid IN (好友)) AND status=0 AND (uid=我 OR visibility=0) AND (created_at,id) < cursor ORDER BY created_at DESC, id DESC LIMIT n+1`（多取一条判断 has_more）；
2. 批量查互动：按 post id 集合一次查出全部 likes/comments，再按「查看者好友集合 ∪ 作者本人」过滤；
3. 昵称解析优先级对齐现有规则：**好友备注 > 用户昵称**（复用 social 模块的备注查询）；
4. media URL 用 OSSSigner 现签发（不落库存预签名 URL）。

**WS 推送**（复用 social notifier，main.go 注入同款闭包）：

| 事件 | 触发 | body |
|---|---|---|
| `moment.new` | 好友发布动态 | `{moment_id, uid, nickname}`，客户端刷红点/提示刷新 |
| `moment.interaction` | 我的动态被点赞/评论 | `{moment_id, actor_uid, action: "like"/"comment", summary}` |

同时写 notifications 表：`type=moment`，Title「朋友圈」，Summary「xx 赞了你的动态」/「xx 评论了你：…」——NotificationCenter 增加该类型图标渲染。

## 6. 服务端模块结构

新建 `service/internal/moments/`，分层对齐现有模块：

```
service/internal/moments/
├── service.go      # 业务逻辑：发布/删除/点赞/评论/Feed 组装/共同好友过滤
├── handler.go      # HTTP 处理器（gin），resp.OK / resp.Fail
└── service_test.go # mockStore 单测（对齐 social/service_test.go 风格）
```

- `service/internal/store/mysql/moments.go`：DAO（posts/likes/comments CRUD + 批量查询）；
- `Service` 依赖注入（对齐 message.Service 的可选注入风格）：
  - `store Store`（自定义接口，便于 mock）；
  - `genID func() int64`（snowflake）；
  - `friends func(uid int64) []int64`（social 注入 ListFriends 的 uid 集合）；
  - `areFriends func(a, b int64) bool`；
  - `notify func(uid int64, event string, data interface{})`（WS 推送）；
  - `oss OSSSigner`（media URL 签发）。
- `cmd/server/main.go` 装配：初始化 momentsSvc → 注入 social 的好友能力与 hub 推送 → 注册 Handler 到 `server.Deps`；
- `internal/server/router.go` 增加 moments 路由组。

**边界保护**（对齐项目现有审计标准）：
- 发布限流：复用 message 的 rateLimiter 思路，单用户每分钟 ≤ 5 条；
- 图片 ≤ 9 张、单图 ≤ 10MB（presign 已校验大小，服务端再校验 media 数组长度与 object_key 归属）；
- 文字 ≤ 2000 字、评论 ≤ 1000 字（按 rune 计数，同 social 备注校验风格）;
- 所有操作先校验作者/好友身份，防越权（删他人动态、看陌生人动态一律 Forbidden）。

## 7. 桌面端设计（desktop_client）

### 7.1 导航与窗口

- `NavRail.vue` 新增「朋友圈」按钮（位于联系人与通知之间），`active === 'moments'`；
- `App.vue` / 主容器新增 `currentView === 'moments'` 分支，渲染 `MomentsWindow.vue`；
- 新组件：

```
src/components/
├── MomentsWindow.vue        # 时间线主窗口（封面栏 + 动态列表 + 发布入口）
├── MomentComposer.vue       # 发布弹窗：文字输入 + 九宫格选图（复用 uploadFile）
└── MomentItem.vue           # 单条动态：头像/昵称/时间/文字/九宫格/互动区
src/composables/
└── useMomentInteraction.js  # 点赞/评论状态管理 + WS 事件合并
src/api/
└── moments.js               # HTTP 封装（对齐 api/social.js 风格）
```

### 7.2 交互要点

- 列表：虚拟滚动或分批渲染（limit 10/页，滚动到底加载）；顶部封面区显示自己头像 + 昵称（微信风格）；
- 九宫格：1 张按原比例缩略、2~9 张三列网格；点击调 `useMediaPreview` 全屏预览；
- 点赞/评论按钮：hover 显示，互动区灰底；评论输入框内联弹出；
- 发布：选图走现有 `presign` 直传（type=`image` 复用或新增 `moment_image`），上传中显示进度占位；发布成功后乐观插入列表顶部；
- 实时性：WS 收到 `moment.new` 时列表顶部出现「有新动态」提示条（点击刷新），收到 `moment.interaction` 时更新对应动态互动区 + 通知中心红点。

### 7.3 本地存储

第一期朋友圈**不入本地 SQLite**（动态时效性强、隐私敏感，拉取成本低）；仅缓存「未读互动红点游标」于 localStorage。P2 视体验再评估入库。

## 10. 风险与备选

| 风险 | 应对 |
|---|---|
| 拉模式在好友数极大时 Feed 查询变慢 | `idx_uid_time` 索引已覆盖；好友上限场景下可加 Redis 缓存最近 N 条或转推模式（写扩散到 feed 表） |
| 共同好友过滤每页 N 条动态 × M 条互动的内存计算 | 批量 SQL + 内存集合过滤，limit≤20 时可控；互动数异常高时截断展示（「查看更多」） |
| OSS 预签名 URL 过期 | media 只存 object_key，展示时服务端签发（对齐 message 模块做法） |
| 图片滥用（大量上传占空间） | presign 已有大小/类型校验 + 发布限流；P2 管理后台可删帖 |
